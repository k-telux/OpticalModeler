# Fresh MZI preview: scope and evidence lessons

This is a sanitized source-review case, not a reproducible public scene, blind forward test, or physical acceptance package. The authoring run used private canonical component resources and project guidance. Its scene, manufacturer-derived assets, private paths, and raw conversation are excluded. The [lesson record](LESSONS.json) preserves the inspected source/report identities and review scope; those identities are not downloadable inputs or independently replayable proof.

## Request and design

The request was to use the existing G1/G2 v18 example as a quality comparator and generate a different high-fidelity optics-only measurement. The chosen design was a Mach–Zehnder phase-measurement layout: source conditioning, first splitter, reference delay and sample arms, recombination, and two optical outputs. Electrical/data/circuit visualization was excluded. The local preview reports described 387 objects, zero electrical objects, and zero linked libraries. Those are reported inventory facts, not a complete independence or physical-assembly proof.

## What the review can establish

Source inspection distinguishes a new source-generated topology and component import path from a presentation edit of the old apparatus. The reported library/name checks are useful but would not alone detect renamed, appended old scene data. A fresh-design workflow must also inspect actual generator inputs and imported asset provenance.

The 20 ray records reported expected endpoint-family hits. The inspected implementation nevertheless skips source-family hits, assigns endpoint error fields the literal `0.0`, and accepts an expected family without validating the particular optical surface. Its design arm-length values are 1.70 m each; these are not measured optical path lengths through refractive media. Therefore the record does not establish independent port accuracy, complete first-hit transitions, or whole-system assembly acceptance.

The delivered preview dimensions were 2048 × 1152 at 16-bit depth. That is not the requested 4K final delivery. Image code used global sharpness/edge statistics and a broad HSV mask with pixel/skeleton-length thresholds. Such a mask can include a colored background or table; the statistics alone do not prove every required beam branch or device detail. A camera crop that improves edge density does not improve mesh precision.

The saved-scene report binds the original preview Blend. Later presentation outputs need their own actual scene/render bindings and applicable geometry comparisons; an earlier reopen report is not a fresh reopen of a later file.

## Reusable corrections

1. Classify new-design versus reconstruction/rerender intent, and keep quality references separate from allowed geometry inputs.
2. Apply optics-only scope to the actual scene and delivered views without losing optical detectors or mechanical support.
3. Measure reopened port/surface witnesses and validate transitions rather than accepting target coordinates or matching family names.
4. Combine global image diagnostics with component close-ups and branch-specific visual evidence; verify delivered resolution directly.
5. Freeze one completed candidate and publish once. A documentation update may preserve these limitations without granting physical or 4K credit.

These are user-scope clarifications and source-observed evidence limitations. They are not claimed to be statistically qualified across multiple new runs.
